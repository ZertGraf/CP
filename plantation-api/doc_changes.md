# Изменения по сравнению с оригинальной документацией

При реализации математической модели бекенда согласно главе 2 документации были разрешены некоторые противоречия и внесены следующие уточнения:

1. **Тип данных индекса здоровья**: В тексте местами встречался тип `INT` и шкала `0-100` (например, в таблице 2.1 иногда упоминалось `health_score INT DEFAULT 100`), но в описании формул (2.7) индекс здоровья $H$ лежит в диапазоне `[0; 1]`. В итоговой реализации `models.go` и миграциях БД принят тип `FLOAT` (поле `health_index`) в диапазоне `[0; 1]`.

2. **Поля таблицы sectors**: В миграции добавлены поля, требуемые для расчета модели из Главы 2, которые отсутствовали в исходном коде: `gdd_cumulative`, `phenophase`, `ks_water`, `ks_aeration`, `deficit_dr`.

3. **Связь объема полива и влажности**: В хендлере полива `watering.go` объем добавляемой воды (в литрах) пересчитывается в миллиметры осадков ($мм = \frac{литры}{площадь (м^2)}$) и напрямую уменьшает дефицит влаги корневой зоны $D_r$. 

4. **Движок симуляции (`engine.go`)**: 
   - Генерация погоды (температура и осадки) упрощена до генерации базовой температуры с небольшим дрейфом и стохастического определения влажных дней.
   - Расчет эвапотранспирации реализован по уравнению Харгривса-Самани.
   - Водный баланс обновляет `DeficitDr` и пересчитывает из него `SoilMoisture` (в процентах) для фронтенда.
   - Фенология: накопление GDD происходит корректно, при достижении порога `Phenophase` переключается.
   - Индекс здоровья обновляется с применением коэффициентов `alphaDrought`, `alphaFlood`, `alphaHeat` и `betaRec` на основе параметров водного и аэрационного стресса.
